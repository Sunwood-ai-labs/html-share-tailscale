HTML共有くん / 実装レポート

AWS依存を外したTailscale刷新

HTML共有くんを、クラウドの常時運用を前提にせず、ローカル実行とTailscale ServeでTailnet内だけに共有する構成へ切り替えた記録です。

2026-08-16 実装・実ブラウザ確認済み Tailnet内限定
01

共有経路をローカル＋Tailscaleに一本化

HTMLのビルド先とレビュー状態をローカルに置き、ループバックで待ち受けるサーバーをTailscale ServeのHTTPSエンドポイントから公開する構成に変更しました。インターネットへ公開するFunnelは使わず、Tailnetに参加している端末からだけアクセスします。

今回の追加 このレポート自体を examples/tailscale-refresh-report.html として登録し、ダッシュボードの一覧から開ける状態にしています。
02

変更の要点

AWSなしAWS SDK・CDK・S3・CloudFront・Lambda・SSMを通常経路から除去
127.0.0.1ローカルサーバーはループバックだけで待ち受け
HTTPSmadesk.example.ts.net:9222 をTailscale Serveで使用
03

実際のデータの流れ

  1. 1. ページ登録html-share page add でHTMLファイルを設定に登録します。
  2. 2. ローカルへ公開html-share publish が .html-share/site と .html-share/data を更新します。
  3. 3. サーバー起動127.0.0.1:4311 のローカルサーバーがダッシュボード、共有ページ、レビューAPIを提供します。
  4. 4. Tailnet内から閲覧Tailscale Serveが https://madesk.example.ts.net:9222 でHTTPS終端し、Tailnet内の端末へ届けます。
04

構成の切り替え

領域旧構成現在の構成
配信AWSサービスを前提にした外部配信ローカルHTTPサーバー＋Tailscale Serve HTTPS
状態外部サービス向けの署名・ペアリング経路ローカルJSON（.html-share/data）
レビュークラウド関数経由Tailnet内のローカルAPIでpush / pull / complete
共有URL外部公開を想定期限付きの /share/<token> をTailnet内だけで発行
05

確認できたこと

  • ビルドと検証
    npm run build と npm run verify が成功。テストは12件成功、Windowsの権限依存テスト1件はスキップ。
  • ライブHTTP
    ヘルスチェック、ダッシュボード、マニフェスト、登録ページをTailscale HTTPS経由で200応答として確認。
  • レビュー往復
    ブラウザからレビューを依頼し、CLIで受信・完了処理を行い、ブラウザから未処理一覧が消えることを確認。
  • 期限付き共有
    html-share share demo-report --days 1 で発行したURLがTailscale HTTPS経由でHTMLを返すことを確認。
06

使い方と現在の境界

  • html-share page add examples/your-report.html --title "レポート名"
  • html-share publish
  • html-share tailscale serve
  • html-share share your-report --days 7
  • html-share review push <message> / html-share review inbox
